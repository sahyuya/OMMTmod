Save, Preview & Submit

Save in-progress work to a local project and submit only finished songs as private drafts to the Oyasai server.

On this page

  • Saving edits

“Save”, “preview”, and “submit” compared

ActionWhat happensSent to server?
SAVE PROJECTCreates an editable .ommt project in OMMT/savesNo
Play / previewChecks the current edit on your own clientNo
UPLOAD DRAFTSends the finished song to the Oyasai server as a private OyasaiMusic draftYes
Source MIDI/NBS files are never overwritten

Edits are never written back to the original .mid / .midi / .nbs. Save an .ommt project to continue later.

Saving edits to .ommt

  1. Load and edit.
    Arrange notes, part names, tempo, volume, pan, and pseudo-release.
  2. Press SAVE PROJECT.
    An .ommt file is created from the current song title. At least one note is required.
  3. Check the confirmation.
    Once saved, you can close the editor and resume later.

.ommt stores not only notes and parts but also tempo, volume/pan, pseudo-release, and view state. File names are sanitized and numbered when they collide.

Example: editing across two days

On day one, finish part arrangement and press “Save project”. On day two, load the saved .ommt from the library's SAVE tab and resume from tempo and volume. No need to reload the source MIDI/NBS.

Back up important projects

Copy .ommt files from OMMT/saves elsewhere so they survive profile rebuilds.

Resuming saved work

  1. Open the SAVE tab.
    Not the MIDI or NBS tab — saves live in OMMT/saves.
  2. Select the .ommt file.
  3. Press LOAD SELECTED PROJECT.
    Double-clicking, or LOAD SAVE at the top, works too.
  4. Verify the restored state.
    Check title, parts, tempo, and notes match the saved session.

To restart from source, use the MIDI/NBS tabs; to continue, use the saves tab.

Preview checklist before submitting

Listen through the whole song, and check these points separately for easier fixes.

  • No notes stray extremely high or low in the overview.
  • Each part's instrument fits its role.
  • The melody is not buried, and no part is too loud.
  • Panned sounds are not pulled too far to one side.
  • Tempo changes are not too abrupt and speeds match your intent.
  • Only pseudo-release notes repeat, with natural intervals and decay.
  • No leftover silence or stray notes at the end.

Play with Space, jump to the start with Home, preview only the selection with P. FOLLOW ON tracks the playhead; OFF pins the view. OFF suits detail fixes, ON suits full checks.

Submitting a draft to the Oyasai server

Check the destination

Draft submission targets the Oyasai server. It cannot send elsewhere (nothing is transmitted), and server permission is required.

  1. Join the Oyasai server.
    Enter a place where you can submit, and open OMMT.
  2. Confirm the final version.
    Check the current edit is finished, including title and parts.
  3. Press UPLOAD DRAFT.
    Progress phases (checking, uploading, verifying, importing) and percent are shown.
  4. Wait for completion.
    Do not close the screen or leave until success or an error appears.

The server validates submissions. Drafts are rejected for missing permission, oversized songs, or unusable sounds. Fix what the error names and resend.

Submit less often

Save to .ommt and preview locally while editing. Submit only when the finished version is confirmed, to avoid piling up drafts.

After submitting

Success creates a private draft. Nothing is published or played to everyone automatically. Further song management happens in OyasaiMusic on the server.

When a supported song plays on the server, players with OMMT may receive it in advance for stable client-side playback. Players without OMMT hear normal server playback. No manual playback selection is needed.

To check whether buffered playback was used, search OMMT/BufferedPlayback in the profile's logs/latest.log. Status never appears in game chat.
